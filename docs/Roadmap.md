# 路线图（Roadmap）

> 目标：从 MVP 到可演示、可逐步扩展的产品雏形。首要是本地离线版，最终在 Vercel 部署（可选）。

## 阶段 0：文档与范围锁定（已完成）

- 完成 `README.md`、`PRD.md`、`GameDesign.md`、`TechPlan.md`、`Roadmap.md`
- 明确 MVP 约束：离线、无后端、回合制、决策卡、事件日志、结局与复盘

## 阶段 1：工程骨架与像素风 UI 基础（目标：`npm run dev` 可跑）

交付：
1. Next.js + TypeScript + Tailwind 配置齐全
2. 全局像素风 UI 组件基元：
   - `PixelFrame`（像素边框容器）
   - `MetricTile`（指标面板）
   - `PixelButton`（统一像素按钮）
3. 页面骨架：
   - 首页（介绍+开始）
   - 游戏主界面占位（指标/决策/日志区域占位）
   - 结局页占位

验收标准：
- 本地可以启动并看到统一像素风页面布局

## 阶段 2：IMC 引擎 MVP（目标：可“离线结算”）

交付：
1. `lib/imc/engine.ts`：回合结算核心（纯逻辑）
2. 指标更新与事件生成（至少覆盖：认知/信任/舆情/销量/长期资产）
3. 结局评价映射：根据指标最终状态输出结局类型 + 能力维度

验收标准：
- 选择不同决策组合时，指标曲线与事件解释能明显不同

## 阶段 3：玩法与动画闭环（目标：可交互可演示）

交付：
1. 决策卡选择与锁定
2. 回合推进（结算弹层 + 事件时间线）
3. 指标变化动画（数字跳动/发光）
4. 结局页完整展示（结局卡 + 能力评估 + 复盘建议）

验收标准：
- 从开始到结束路径可完整走通，且离线刷新可恢复状态

## 阶段 4：舆情/危机简化增强（目标：教学更贴近 IMC）

交付：
1. 加入危机事件（简化阈值触发 + 危机预案缓解）
2. 强化联动规则（广告-内容、公关-信任、促销-长期资产）
3. 调整数值平衡，避免单一策略碾压

验收标准：
- 玩家能够通过“早期建立信任 + 稳定舆情”的策略获得更优长期结局

## 阶段 5：可用性与扩展准备（目标：更像产品）

交付：
1. 可读性优化（布局、移动端、字体与对比度）
2. 可配置难度与回合数（轻量参数化）
3. 支持多开局/多存档槽（P1 或 P2）
4. 文案与教学颗粒度优化

## 阶段 6：上线（可选）

交付：
- Vercel 部署（不依赖后端）
- 可公开访问的静态运行

## 风险控制（贯穿全程）

1. 数值模型避免“无差异”
2. 教学解释避免过长
3. 动画避免遮挡关键信息（优先可读性）
